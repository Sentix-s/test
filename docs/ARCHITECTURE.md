# Архитектура JARVIS

## 1. Техническая оценка предложенного стека

Оценка под целевой ПК: RTX 3060 12 GB, i5-12400F (6P/12T), 32 GB DDR4, Windows 11.
Наличие Windows-колёс (`win_amd64`) для всех пакетов проверено по PyPI.

| Компонент | Предложено | Решение | Обоснование |
|---|---|---|---|
| LLM | Qwen 7–8B 4-bit | **Qwen3-8B Q4_K_M** (`qwen3:8b`), запасная `qwen2.5:7b-instruct` | Qwen3-8B заметно лучше в tool calling и русском. ~5.2 GB весов + ~1.2 GB KV-кэша на 8k контекста ≈ 6.5 GB VRAM. Режим «thinking» выключен по умолчанию (`think: false`) — для голоса критична задержка. |
| Рантайм LLM | Ollama | **Ollama** ✔ | Нативный tool calling, стриминг, управление VRAM через `keep_alive` (нужно для профилей и выключения), сервис в трее. |
| STT | faster-whisper | **faster-whisper** ✔, модель `large-v3-turbo` int8_float16 (~1.6 GB VRAM); в ECO — `small` на CPU | Лучшее качество русского среди локальных. Вместе с LLM укладывается в 12 GB с запасом ~3 GB. |
| VAD | — | **Silero VAD** (onnx) | Нужен для конца фразы и таймера тишины; whisper сам по себе не детектирует паузы. |
| Wake word | openWakeWord | **openWakeWord** ✔ (ONNX-бэкенд) | На Windows нет tflite-runtime — только `inference_framework="onnx"`. Готовая модель есть лишь для «hey jarvis»; для одиночного «Jarvis» и смены слова нужна дообученная модель (скрипт обучения openWakeWord) — в Phase 2 закладываем загрузку пользовательских `.onnx`. |
| TTS | Kokoro или Piper | **Piper** для русского (голоса `ru_RU-irina/denis/dmitri/ruslan`), **Kokoro** — опционально для английского | Kokoro не поддерживает русский. Piper работает на CPU в реальном времени и не занимает VRAM. |
| Эхо собственного голоса | — | Полудуплекс: микрофон «глушится» на время TTS + 300 мс хвоста; barge-in — Phase 6 | Надёжнее программной AEC на произвольных колонках. |
| GUI | PySide6 | **PySide6** ✔ (+ QML/QPainter для анимаций ядра) | LGPL, нативный трей, OpenGL. |
| Управление UI | pywinauto / UIA | **pywinauto (UIA backend)** + `pywin32`/`ctypes` для окон и горячих клавиш | |
| Office | UI Automation | **COM-автоматизация (pywin32)** для Word/Excel/PowerPoint; fallback без Office — `python-docx` / `openpyxl` / `python-pptx` | COM надёжнее и быстрее UI Automation, результат проверяется чтением документа обратно. |
| Браузер | Playwright | **Playwright** ✔ (отдельный профиль) | |
| Память | SQLite | **SQLite** ✔ (WAL); в Phase 6 — эмбеддинги через Ollama (`nomic-embed-text`/`bge-m3`) | |
| Почта | OAuth | **Gmail API (google-auth-oauthlib) / Microsoft Graph (MSAL)**, токены — в Windows Credential Manager через `keyring` | Пароли не хранятся. |
| Антивирус | Windows Defender | `MpCmdRun.exe -Scan -ScanType 3 -File <path>` | LLM не считается антивирусом. |
| Мониторинг GPU | — | **NVML (`nvidia-ml-py`)**; в Phase 1 — `nvidia-smi` | |
| Установщик | — | **PyInstaller + Inno Setup** (Phase 7) | |
| Python | — | **3.12** (поддерживается 3.11) | numpy ≥ 2.5 выпускается только для 3.12+, все прочие зависимости имеют колёса cp312 win_amd64. |

### Бюджет VRAM (12 GB)

| Профиль | LLM | STT | Итого |
|---|---|---|---|
| BALANCED | qwen3:8b, 8k ctx ≈ 6.5 GB | large-v3-turbo ≈ 1.6 GB | ≈ 8 GB, ~4 GB остаётся играм/браузеру |
| PERFORMANCE | 16k ctx ≈ 7.7 GB | large-v3-turbo | ≈ 9.5 GB |
| ECO | выгружается после ответа (`keep_alive` 1–2 мин) | small на CPU | ≈ 0 GB в простое |

## 3. Ключевые решения

**Инструменты вместо команд.** Любая возможность — функция с `@tool(risk=…)`.
Схема для модели строится из сигнатуры (`Annotated[str, "описание"]`,
`Literal[...]`, значения по умолчанию). Новая фаза = новый модуль инструментов +
строка в `register_builtin_tools`; агент и GUI не меняются.

**Агентный цикл** (`jarvis/ai/agent.py`): модель → `tool_calls` → проверка
разрешения → выполнение → результат обратно модели → … до ответа без
инструментов или лимита шагов (`max_tool_iterations`, затем финальный ответ
без инструментов). Ошибки инструментов не роняют цикл — они возвращаются
модели как `ERROR: …`, чтобы она исправилась или честно сообщила о неудаче.
Если шаблон модели не сработал и Qwen выдал `<tool_call>{…}</tool_call>`
текстом — вызов распознаётся, разметка не показывается и не озвучивается.

**Безопасность.** `SAFE` и `MODERATE` выполняются автоматически (MODERATE —
по желанию с подтверждением), `DANGEROUS` — только после явного «да»; без
интерактивного пользователя — отказ. Проверка может повышать риск
динамически (например, shell-инструмент в Phase 4 классифицирует команду).
Каждое решение пишется в `audit_log`; поле `undo` зарезервировано для отмены
(Phase 4: перемещение в корзину вместо удаления, обратные операции для
перемещения/переименования).

**Остановка.** `CancelToken` — единый механизм для кнопки «Стоп», Ctrl+C,
аварийной остановки и выключения: закрывает HTTP-поток к Ollama немедленно
(генерация прекращается на сервере), инструменты проверяют токен между шагами.

**Потоки.** Агент выполняется в рабочем потоке; UI-поток рендерит события и
отвечает на запросы подтверждения через очередь. GUI в Phase 3 использует ту
же схему через Qt-сигналы.

**Память контекста.** В модель уходят последние N сообщений в пределах
бюджета символов (`history_char_budget`), контекст никогда не начинается с
«осиротевшего» результата инструмента; факты из долговременной памяти
подставляются в системный промпт.
